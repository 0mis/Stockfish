# Accumulator alternative CI draft v1

Unpublished, untriggered draft. Native/history acceptance and strength remain pending real CI plus independent review. Both current matched screens and their selection rule remain fixed.

One Windows 2022 job, maximum 45 minutes, runs only on pushes to `research/test1757-accumulator-ci` in `0mis/Stockfish`. Permissions are `contents: read` and `actions: read`. The reference download action alone receives `github.token`; the helper never receives or logs it. The driver is checked out at the triggering SHA, while engine source is pinned to commit `7a2c542da605b587558f55460901e215584fd5ec` and verified tree `a6de349d12f7e320b5c757255139536a94cfaab5`.

The reviewed draft-v3 fixes remain: `HEAD:` for Windows Git tree lookup, absolute native executable paths, exact Windows relative external EvalFile paths, pinned action commits, source/GPL packaging before native work and a strict artifact whitelist. The same sparse patch and 22 probes retain their prior hashes. Donor18cd and edited034f expected ordinary benches are fixed at 3464885 and 2854625, twice each; perft4 is fixed at197281. All44 exact static integers must match the existing probe expectations. Full trace/bucket audit remains independent.

PGO uses the unchanged Makefile and its default `stockfish.exe bench` inputs. A command-line `PGOBENCH` wrapper resolves that same current-directory executable to an absolute Windows path, passes only `bench`, captures complete stdout/stderr plus instrumented executable hashes/exit status, and forwards the full pipes to the Makefile's temporary report. Its usual tail and cleanup still run. Profiling positions, clocks/depth/defaults and C++ are not edited. Full PGO logs survive in the artifact.

The SHA-pinned accepted reference is obtained from run42543250921's exact named artifact. Its executable must be142322823 bytes with SHA-256 `12a8e7bfdd9b1189b4350bd9ebef3501be1e89bd5fa41dcb56921f85ba23869a` before and after checks. Artifact availability/retention must be checked before launch; if missing, the job fails without replacing the reference.

The finite history driver uses pinned `chess==1.11.2` only for legality/parsing. Its PyPI source distribution hash is locked, installed on the runner without cache; no local package installation is part of drafting. Eight synthetic/legal histories cover quiet moves, captures, both castles, en-passant, queen promotions and underpromotions for both colors. Every forward prefix is searched, followed by repeat, rewind one ply and reuse. Each engine/network/case gets a fresh process with T1/H64 and identical options; no clear/newgame occurs between its repeated/rewound searches. Actual `go depth 6` commands wait for `bestmove`, followed by `readyok`, before another go or quit. Searches internally exercise make/unmake; rewind is expressed through a shorter legal UCI history.

There are74 searched checkpoints per network/executable:296 completed searches overall. Candidate and reference must match exact final-per-depth nodes, score kind/value/bounds, PV, seldepth, bestmove and ponder. Timing/NPS are retained raw but excluded from equality. Both complete streams, commands, process exits and result rows are retained. This is a bounded regression check, not proof of every accumulator branch or of playing strength.

The one-day artifact contains only the new executable, small evidence/JSON/commands, full PGO/history logs, GPL/AUTHORS and full pinned corresponding source with driver files. Neither external NNUE nor the reference executable is eligible for upload. The new executable embeds a large network; artifact storage needs review. MSYS2 GCC is recorded rather than version-pinned. Runtime compilation, hosted-tool availability, reference retrieval and timeout margins remain untested by this offline draft.
